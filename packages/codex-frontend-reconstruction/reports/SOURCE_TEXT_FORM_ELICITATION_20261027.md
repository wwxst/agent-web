# 2026-10-27 — Source formElicitation plain-text questions integrated with host drafts and Electron

## Exact original Windows source evidence
- Provided zip `frontend/webview/assets/mcp-server-elicitation-request-panel-7318114289f7.js` `at` dispatches `formElicitation`, `openaiForm`, `legacyOpenAIForm` to the full `request-panel` renderer `Ae`.
- `frontend/webview/assets/request-panel-26c348285c1a.js`: exported `t` (`$r` -> `ei`) renders the form. `_n` initializes draft `kind,fieldIndex,values,customDrafts,fileOptions`; `vn` validates by kind; the original `formElicitation` uses the schema validator imported as `Mt`. `Yr` shows form message, previous/next question and `{current} of {total}`; `Wr` -> `ur` renders field typed by schema; the string branch reads `field.title`, `field.description`, `minLength`, `maxLength` and `Qn` input. `wn` shows `Skip for now` for a non-last question, `Continue` for the last question and `Cancel` for the simple form. `ei` only calls accept with validated content, `decline` or `cancel`, and supports Cmd/Ctrl+Enter and Escape.
- Original `app-initial-5851df3f6cb1.js` `q2t` (export `iSr`): `accept` yields `{action:'accept',content:answers,_meta:null}`, `decline` and `cancel` yield `{action,content:null,_meta:null}`. Generic MCP approval envelopes have a different wire format.
- Original `ei` stores drafts above individual React field row rendering in source `Ge` (keyed by `hostId,conversationId,requestId`) rather than exclusively in a mounted field component.

## Implemented source-driven integration
- `SourceTextFormElicitationModel.ts` projects only safe `formElicitation` object schemas where **all** properties are plain strings without custom format, enum, file options, arrays, private x-* extensions or confirmation metadata; 1–12 questions, strict required/minLength/maxLength, message/title/description. Unsupported layouts remain read-only host pending entries. `openaiForm` and `legacyOpenAIForm` are **not** silently downcast to text fields.
- `SourceTextFormElicitationCard.tsx` + CSS renders the original one-question-at-a-time structure in the **existing** React `ConnectedConversationMessageRenderers` and canonical virtualized `LiveConversationSource`: next/previous navigation, progress, field description, required error, Skip for now, final validation, Continue, Cancel and Escape, Cmd/Ctrl+Enter. Offline browser permits local editing and navigation but cannot submit because no backend is attached.
- `SourceTextFormDraftStore.ts` owned by `SourceConversationHostEventBridge` provides request-scoped, bounded session drafts. Synchronous typed edits persist values and current question across row unmount, virtualized remount and conversation switch. `elicitation-settled` and `clear-thread` clear only authoritative matching draft requests. Source schema changes invalidate an old draft.
- `demo/adapters.tsx` directly projects live host `pending-elicitation` records using the existing source event bridge. It uses exactly the same host-owned transcript rendering as other cards. The toolbar fixture is labeled synthetic and is only used to verify UI without a real Agent producer.
- `desktop/textFormReply.cjs` + `desktop/main.cjs` / `preload.cjs` add isolated, exact-five-field, bounded `agent-web:text-form-reply` with source q2t actions, string-only content, prohibited special keys and trusted main-frame validation. Native main **fails closed** with `TEXT_FORM_BACKEND_UNAVAILABLE` unless explicitly connected to an independently verified Agent reply transport; native tests never grant acceptance. Backend must additionally revalidate answers against the authoritative pending form schema before accepting.

## Tests
- Core: source field schema projection and rejection of unsupported formats; min/max/required/optional content; q2t acceptance vs cancel/decline shapes; host ID isolation.
- Core draft store: values and field index survive virtual unmount, schema changes invalidate drafts, unrelated hosts/threads do not cross-contaminate, authoritative settlement and clear-thread clean up.
- Chromium: real timeline 2-field fixture exercises local typing, validation, previous/next, values retained and read-only submit; separate test switches to review thread and returns to original with values/current question restored.
- Native Electron on Linux and Windows: main emits authenticated host-originated pending form event -> context-isolated preload -> existing React transcript; native form accepts local text and attempts Continue/Cancel over real typed IPC; backend-unavailable error retains request/draft; host update changes schema; host settlement removes the same canonical row; malformed renderer IPC is rejected.

## Explicit limitations / next work
- This is an **actual interactive source subset** of `formElicitation` plain text fields; not a fully recovered form system. Numeric, boolean, enum/choice, array, file uploads/options, optional custom answers, confirmation presentation, `openaiForm`, `legacyOpenAIForm`, private host validations, deadline auto-resolution, and the real Agent backend remain unimplemented. Never render a misleading success state for them.
- Browser widget UI and Electron shell must still be compared pixel-by-pixel against running original Windows Codex; CI UI snapshots alone are not original parity.
- Draft stays session-local in host bridge, not persisted across application restart; long-term persistence requires verified host storage policy and consent.
- Stacked draft PR on #47; no merge to main.
