### Proven example corrected in this audit branch

Original `app-primary` `AFt` mounts via **`Jd({container: document.body})`** with `pointer-events-none fixed top-2 z-[55] flex justify-end`, `right:16+sidePaneInset.right`, inner `max-w-[70vw]` and host zoom. Earlier recovered `demo/App.tsx` rendered its search bar as a child of `.demo-main` even though its CSS used fixed positioning. We now retain the same search state, controls, virtualizer, and preloaded native menu route, but mount via React `createPortal(...,document.body)`, use pointer-transparent fixed outer wrapper and pointer-active inner bar. Native Electron smoke asserts actual DOM placement, fixed geometry, z-index, width and pointer behavior. This is a **limited source-backed DOM correction**, not full `AFt` source parity: side-pane inset, host zoom, domain-toggle logic and palette/spacing remain unverified.

## Risk review: avoid claiming completion too early

1. **Tests vs parity**: CI on #8 previously passed 420 core, 5 demo, 27 Chromium, 14 Linux Electron, 14 Windows Electron; these use synthetic UI/host data, not a full original-client oracle. For the current branch run final-head CI separately and inspect logs before claiming even those gates.
2. **History continuity**: earlier reports used 87/92/140/275 test counts and claims that no Electron app was runnable. Those are truthful *historical checkpoints* but are **not current HEAD**. Use this audit + live branch/ref/CI status instead.
3. **Branch hygiene**: PRs #6 → #7 → #8 and this audit branch form a dependency chain. Do not merge straight to main, reimplement prior features, or delete open branch bases. Merge or rebase in order only after user approval.
4. **Real backend boundary**: neither original proprietary `codex_desktop` service nor the user's Agent backend protocol is supplied as an authorized working runtime within this task. Never invent event schemas, bypass approvals, or label mock execution a completed feature.
5. **Minimum full-system acceptance**: built frontend on real Windows must launch; real host turns/tool actions/interrupts/approval/recovery must be exercised; multi-turn scroll and keyboard UI tested; same-version Codex visuals compared at exact viewport, theme, scale, state and content. Until these exist, label status **independent demo shell and integrated recovered subsystems, NOT completed Codex frontend**.
